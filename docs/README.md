Defines what the system is and how it behaves.

- **Vision** → Purpose, scope and direction of the product
- **Business Rules** → Core logic and constraints
- **Data Model** → Structural representation of the system
- **UI Guidelines** → Design principles and interface consistency

## 🧭 How to navigate

- Start at **Product** to understand what Encaja is
- Move to **Engineering** to understand how it is built
- Review **MVPs** to follow feature evolution
- Check **Releases** for stable versions
- Use **Tasks** to see current and recent work

---

## 🧩 Documentation Principles

- **Single source of truth** → Avoid duplicated definitions
- **Clarity over verbosity** → Keep documents focused and actionable
- **Chronological integrity** → MVPs and Releases must reflect real history
- **Consistency** → Naming, structure and terminology must remain uniform

---

## 🚀 Notes

This structure is designed to scale with the product. 
New documentation should respect existing domains before creating new ones.
